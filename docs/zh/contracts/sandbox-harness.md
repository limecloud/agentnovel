# 沙盘 Harness

`sandbox` 是发布前模式。作品尚未进入不可逆读者时间线，作者可以推倒、重排、替换和重挂结构。沙盘 Harness 的目标是让这种自由变得可控。

## 1. 权限边界

| 对象 | sandbox 权限 |
| --- | --- |
| 未发布章节 | 可重写，但必须通过 proposal/apply。 |
| 章节顺序 | 可重排，但要生成影响分析。 |
| 伏笔链 | 可新增、移动、删除、合并。 |
| 人物弧光 | 可重构状态机和关键转折。 |
| canon | 候选可批量整理，confirmed 修改需审批。 |
| exports | 可重新生成，不反向覆盖正文。 |

## 2. 沙盘诊断

沙盘 Harness 应支持全局结构扫描，形成小说体检报告：

- 主线是否清楚。
- 卷册目标是否支撑主线。
- 章节是否有叙事功能。
- 人物状态变化是否有因果。
- 伏笔是否有根、有延迟、有回收。
- 信息释放是否过早、过晚或重复。
- 节奏是否存在长平段或高潮过密。
- 黄金三章是否能留住目标读者。

诊断不能只给“不错”“需要加强”。每个发现必须带目标引用、证据、严重度和建议动作。

## 3. 意图到方案

作者输入修改意图后，沙盘 Harness MUST 生成候选方案，而不是直接改稿。

示例意图：

```text
让女主更早显露危险感，但不要破坏第 12 章反转。
```

候选方案应包含：

| 字段 | 说明 |
| --- | --- |
| `optionId` | 稳定方案 ID。 |
| `summary` | 方案概述。 |
| `edits` | 涉及章节、场景、设定或伏笔。 |
| `benefits` | 对作者意图的收益。 |
| `costs` | 需要牺牲或重写的内容。 |
| `risks` | 人物可信度、节奏、读者误解等风险。 |
| `impactRef` | 对应冲击波分析。 |

## 4. 结构操作

沙盘 Harness 可以提出以下操作：

- 章节提前或后移。
- 场景拆分、合并或换视角。
- 伏笔前置、延后、删除或增加回收点。
- 人物转折重排。
- 信息差重新分配。
- 黄金三章重构。

但执行规则始终是：

```text
作者意图 -> 候选方案 -> 冲击波分析 -> 作者确认 -> proposal/apply -> revision record
```

## 5. 退出沙盘

当作品进入发布前锁定时，应生成：

- 最近一次小说体检报告。
- 未解决高风险 issue 列表。
- 已确认 canon 快照。
- 导出预检结果。
- 即将进入 `timeline` 的只读章节范围。

发布完成后，已发布章节进入时间线 Harness 的只读边界。
