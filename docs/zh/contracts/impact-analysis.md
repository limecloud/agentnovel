# 冲击波分析

冲击波分析用于回答一个问题：如果现在改这里，哪里会跟着变？

它是 Harness 的安全带，尤其适合长篇小说的结构重构、伏笔移动和人物弧光调整。

## 1. 触发场景

以下动作 SHOULD 触发冲击波分析：

- 章节提前、后移或删除。
- 关键事实提前暴露或延后暴露。
- 伏笔新增、删除、换承载章节。
- 人物关系或立场提前变化。
- 世界规则修改。
- 已发布内容相关的 future fix。

## 2. 影响对象

| 对象 | 示例 |
| --- | --- |
| 章节 | 第 7 章信息提前影响第 12 章反转。 |
| 场景 | 某场景失去冲突或信息功能。 |
| 人物 | 角色知道的信息变化导致后续选择不可信。 |
| 伏笔 | 原回收点失效，或新增无根伏笔。 |
| 时间线 | 事件顺序与旅行时间冲突。 |
| 设定 | 能力规则、组织边界或物件状态冲突。 |
| 读者 | 悬念提前破掉、期待被误导或爽点延迟。 |
| 发布 | 已发布章节不可改，只能 future fix。 |

## 3. 分析输出

冲击波分析至少包含：

- 作者意图。
- 拟议改动。
- 当前 lifecycle mode。
- 受影响对象列表。
- 风险级别。
- 必须同步更新的文件或事实源。
- 可接受的替代方案。
- 推荐执行顺序。

## 4. 风险分级

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| low | 局部措辞或单场景影响。 | 可生成 proposal。 |
| medium | 影响相邻章节或局部人物状态。 | 需要作者确认。 |
| high | 影响主线、反转、核心人物或多个伏笔。 | 需要多方案比较。 |
| blocking | 与已发布事实或核心设定冲突。 | 默认拒绝或转为 timeline 修复。 |

## 5. 示例

```text
意图：第 7 章提前暴露女主真实身份。
影响：第 12 章身份反转失去冲击；第 9 章男主的错误判断不再可信；第 15 章阵营选择需要重写动机。
建议：不要直接暴露身份，改为暴露一个危险能力副作用，并在第 12 章回收身份真相。
```

这个输出可以进入 `impact-analysis.schema.json`，并被 intent plan、revision record 或 timeline iteration 引用。
