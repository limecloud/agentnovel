# 小说驾驭引擎

`Novel Harness Engine / 小说驾驭引擎` 是 Agent Novel v0.1.2 的核心概念。它不是一个写作模型、一个提示词包或一个自动改稿按钮，而是一套让作者驾驭长篇复杂性的工程层。

`Harness` 在这里保留三重含义：

| 含义 | 对小说系统的映射 |
| --- | --- |
| 马具 / 挽具 | 把创作冲动、故事骨架、人物弧光和读者反馈套进可牵引的结构。 |
| 驾驭 / 利用 | 作者不是被剧情复杂度拖走，而是能控制节奏、信息释放和修订方向。 |
| 执行框架 / 控制壳 | 每次诊断、模拟、修订、发布都留下输入、证据、方案、风险和决策记录。 |

`Forge` 不是主隐喻。它表示构建、调校、验证 Harness 的工作台：作者在这里给作品装上可控的牵引结构。

## 1. 产品定位

小说驾驭引擎是作者的“副驾驶”，不是替代作者的“自动驾驶”。它要完成四件事：

1. 看见骨架：把主线、支线、章节序列、信息释放和冲突推进变成可检查结构。
2. 看见内脏：把人物动机、人物弧光、伏笔链、世界规则和读者预期变成可追踪状态。
3. 模拟改动：在改正文前预测影响范围，避免“改一章，崩全书”。
4. 固化决策：把作者意图、多方案比较、选择原因和拒绝原因写入修订记录。

它不应该做：

- 静默覆盖正文。
- 替作者选择唯一剧情方向。
- 把诊断写成泛泛评价。
- 把读者评论当成必须服从的指令。
- 在发布后回改已发布章节而不留下不可逆边界。

## 2. 三层 Harness

### 2.1 Story Harness

Story Harness 驾驭故事骨架。

它关注：

- 主线目标、阶段目标和卷册目标是否一致。
- 章节顺序是否支撑情绪、信息和冲突递进。
- 每章是否有明确叙事功能，而不是只增加字数。
- 信息差是否被设计，而不是被遗忘。
- 伏笔是否有根、有延展、有回收。

输出应该落到章节目标、场景目标、结构问题、冲击波分析或修订 proposal。

### 2.2 Character Harness

Character Harness 驾驭人物弧光。

它关注：

- 人物在每章的目标、信念、关系、能力、创伤和边界。
- 人物状态变化是否有事件因果。
- 人物选择是否符合当前已知信息。
- 关系推进是否有场景证据。
- 反转、黑化、和解、成长是否有前置铺垫。

Character Harness 应形成状态机：横轴是章节或场景，纵轴是人物状态，不允许只写“人物更丰满”。

### 2.3 Reader Harness

Reader Harness 驾驭读者体验。

它关注：

- 黄金三章是否建立钩子、主角共鸣、世界沉浸和继续阅读动机。
- 爽点、悬念、压迫、释放是否形成节奏频谱。
- 读者预期是否被管理，而不是被误导到不可回收的方向。
- 评论、吐槽、弃读信号映射到哪个结构问题。
- 发布后如何用未来章节补强，而不是直接回改过去。

Reader Harness 不等于“讨好评论”。它把反馈转成证据和风险，由作者做最终判断。

## 3. 生命周期模式

小说驾驭引擎必须知道作品处于哪个生命周期。

| 模式 | 阶段 | 权限 | 典型动作 |
| --- | --- | --- | --- |
| `sandbox` | 发布前 | 可重排、可重写、可重挂伏笔 | 全本体检、结构重构、章节重排、人物弧光重写 |
| `timeline` | 发布后 | 已发布章节只读，未来章节可写 | 读者反馈映射、回潮声明、未来章节补强、预期重塑 |

这两个模式不是 UI 主题，而是写作权限和修订策略的根约束。

## 4. 与现有工作面的关系

| 工作面 | Harness 介入方式 |
| --- | --- |
| 写作 | 约束章节目标、场景目标、信息释放和当前人物状态。 |
| 知识 | 将素材和问答编译为可被 Harness 检索的证据层。 |
| 拆书 | 提供黄金三章、节奏频谱和同类作品结构参照。 |
| 设定 | 维护人物状态机、伏笔链、时间线和世界规则。 |
| 修订 | 承载小说体检、A/B/C 方案、冲击波分析和作者决策。 |
| 发布 | 锁定发布前状态，发布后切换到 timeline 不可逆约束。 |

## 5. 最小实现要求

兼容实现至少需要：

- 在项目级记录 `lifecycle.mode`。
- 能生成小说体检报告。
- 能把作者修改意图转为至少两个候选方案。
- 能为结构改动生成冲击波分析。
- 能区分发布前可重构和发布后不可回改。
- 能把读者反馈映射为 issue、proposal 或 timeline iteration。

## 6. 质量判断

一个 Harness 输出合格，必须满足：

- 有目标：说明解决哪个作者意图或读者风险。
- 有证据：引用章节、场景、设定、反馈或导出版本。
- 有边界：说明哪些内容不能自动改。
- 有方案：提供可比较选项，不只给批评。
- 有影响：预测修改会影响哪些章节、人物、伏笔和读者理解。
- 有决策：记录作者选择、拒绝或延后原因。
