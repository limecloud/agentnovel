# 写作工作面

写作工作面是 Agent Novel 的主战场。正文编辑器在中央，Agent 侧栏只辅助，不抢焦点。

## 结构列

- 章节树。
- 场景列表。
- 当前章节目标。
- 本章状态。
- 当前 lifecycle mode：`sandbox` 或 `timeline`。
- Harness 提示：本章承担的结构功能、人物状态、伏笔状态和读者体验风险。

## 主工作面

- 正文编辑器。
- 选区操作。
- 行内提议。
- 提议接受/拒绝。
- 差异对照。
- 当前场景的目标、冲突、信息释放和情绪方向。

## 章节代理

章节代理可以：

- 基于当前章节目标续写。
- 改写选区。
- 补强场景目标。
- 根据 canon 和 compiled memory 控制连续性。
- 调用 Story Harness 检查信息释放和章节功能。
- 调用 Character Harness 检查人物知道什么、相信什么、能做什么。
- 保存 proposal，不直接覆盖正文。

## Harness 约束

写作时，Harness 不是额外聊天，而是当前章节的约束层：

| 约束 | 写作含义 |
| --- | --- |
| 章节功能 | 本章必须推进什么主线、关系、伏笔或主题。 |
| 场景目标 | 当前场景必须改变什么状态。 |
| 信息差 | 作者、角色、读者分别知道什么。 |
| 人物状态 | 角色当前目标、信念、关系和能力边界。 |
| 伏笔状态 | 本章种下、加强、误导或回收哪些线索。 |
| 读者体验 | 本章是否承担钩子、爽点、压迫、释放或回潮声明。 |

## 编辑器协议

Tiptap 或其他编辑器只是 UI 状态源；保存后才通过应用层回写章节文件。右栏消息变化不应导致编辑器实例重建。

在 `timeline` 模式下，已发布章节应以只读或受限勘误状态显示；任何影响剧情事实的修改都必须转为未来章节 proposal 或 timeline iteration。
